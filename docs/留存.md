二、核心强制规则（审核必过底线）
2.1 触发规则（严格遵守）
仅支持用户手动主动触发：禁止页面加载自动弹窗、禁止定时弹窗、禁止进入页面自动唤起授权。
合法触发场景仅两种：用户正向操作完成后、用户主动点击提醒按钮。
2.2 一次性订阅7天硬性规则（官方机制）
- 用户每次同意授权，仅拥有7天有效推送额度
- 7天内未使用该额度推送，额度自动过期作废，不可恢复
- 7天内成功推送1次消息，额度立即消耗清零
- 额度过期/消耗后，必须用户再次手动授权才可继续接收提醒
2.3 双7天独立规则（不冲突）
- 授权7天有效期：控制推送额度是否可用
- 拒绝7天冷却期：控制前端弹窗是否可再次弹出
三、订阅授权触发时机（打卡专属留存逻辑）
所有时机均为用户主动正向操作后触发，不阻塞业务、不强制授权。
3.1 时机一：新建心愿成功（首次授权）
用户完成心愿信息填写、创建心愿成功后，唤起订阅授权弹窗。
用户同意：获取7天有效打卡提醒推送额度，用于后续打卡召回。
用户拒绝：不影响心愿使用，记录拒绝时间，7天内不再弹窗。
3.2 时机二：每日打卡成功（核心留存闭环）
用户完成当日存钱打卡、打卡状态更新成功后，唤起订阅弹窗。
业务目的：为下一次打卡预存7天提醒额度。
用户持续打卡 = 持续刷新7天授权有效期，长期拥有提醒权限，大幅提升留存。
用户断签不操作 = 额度自然过期，不再骚扰沉睡用户。
3.3 时机三：心愿详情页手动按钮（兜底入口）
页面常驻【开启打卡提醒】按钮，仅用户主动点击可触发弹窗。
按钮状态交互：
- 有有效额度（7天有效期内）：按钮置灰，文案「7天打卡提醒已生效」
- 无有效额度、不在冷却期：按钮可点击，文案「开启打卡消息提醒」
- 7天拒绝冷却期内：点击提示「暂时无法开启，7天后重试」
四、禁止弹窗场景（防违规、防骚扰）
- 页面初始化、首页进入、列表进入，禁止自动弹窗
- 用户操作失败（创建失败、打卡失败），禁止弹窗
- 用户7天内已拒绝该模板，禁止重复弹窗
- 心愿到期、预警场景，只消耗已有额度推送，不主动弹授权
- 用户全局关闭小程序通知，不再自动弹窗，仅保留手动入口
